Setting Up Carmen Java Help Project


There are two primary things to consider when setting up Carmen Help projects:

  1. How best to organize help information files to organize them logically and conveniently for authoring
  2. How to organize help information to best package it for delivery to your users.
  3. How to package the help (Standard Way with JavaHelp)
  4. How to package the help (using Helen in CARMEN)
  5. How to create new Carmen Java Help Projects
  6. Setting Online help with F1 key in Carmen windows

 

1. Authoring

The JavaHelp system is based on independent files. Topics are contained in files that are displayed in the help viewer one file at a time.

It is a good idea to group related topics together to keep them organized and to make it as easy as possible to link the topics together.

The JavaHelp system uses URLs. A URL can resolve to the contents of a file in a file system, a file on the web, or a portion of a JAR file, or it can even be generated dynamically by a server. In CARMEN, those topics are organized to make it easy to package them into a compressed JAR file for delivery to users. One per each supported language. For these reasons, it is best to organize topics in a folder hierarchy that you can "tear off" and place in the JAR file.

1.1 Links

The destination of a link to another topic in the helpset should be specified relative to the file that contains the link. The following is an example of such a relative link:


<A HREF="../subtopicB/topic.html">new topic</A>

Only relative links remain valid when the topic hierarchy is packaged into a JAR file and then installed on the user's computer.

Do not specify links to other topics by using an absolute link. For example, the following link uses a full path name to the destination of the link and it will fail when you move to the project source folders:


<A HREF="C:/product/help/subtopicB/topic.html">new topic</A>

 

1.2 File Separators ("/" vs. "\")

All files in a JavaHelp system are specified as URLs, which use the forward slash ("/") as the separator between elements (files) in a hierarchy. Although in some cases a backslash ("\") works on Windows platforms, if files that contain such references are installed on a different platform, the references no longer work.

1.3. Type of files

Java Help works with HTML files. Unfortunately, there is no support for XML files.

 

2. Organisation

In addition to the topic files, the help information includes metadata files that contain information about the help system. Where you locate these metadata files can affect how you package, deliver, and update the help information for your users. In JavaHelp systems there are two kinds of metadata:

  • Navigational data
  • Helpset data

2.1 Navigational Data

Navigational data files contain information that is used by the JavaHelp system navigators. The standard JavaHelp system navigators are:

  • Table of contents (toc.xml)
  • Index (index.xml)
  • Full−text search (JavaHelp search directory)
  • Glossary (glossary.xml)

Each of these navigators has a metadata file associated with it that contains navigational data. These metadata files should be located in close proximity to the topic files to make it easier to package them into JAR files with the topic files for delivery to customers.

In CARMEN Help System, those files are located in the root directory of each language help project 

2.2 Helpset Data

Helpset data is information that the JavaHelp system needs to run your help system. It is contained in two files:

  • Helpset file (helpset.hs)
  • Map file (map.xml)

When the JavaHelp system is activated by your application, the first thing it does is read the helpset file. The helpset file contains all the information needed to run the help system. As you can imagine, the application must be able to find the helpset file after the product is installed on your user's system. The helpset file contains the location of the map file and, in most cases, the map file is read when the helpset is initialized. The map file is used to associate topic IDs with URLs (paths to HTML topic files).

 

3 Packaging a Helpset into a JAR File (JavaHelp standard way to do it)

You can package your help information into JAR files for delivery to users. Usually, you package the helpset file and map file in the JAR file along with the topic files and navigational files. On the JavaTM 2 Platform, the jar: protocol makes various packaging options available. Including the helpset and map files in or or excluding them from the JAR file has an effect on how you deliver the help information and how you can later update it. The following two sections describe some of the issues to consider when making that decision.

3.1 Helpset File

Under some installation conditions, the helpset file could be excluded from the JAR file, while the map file is included.

The helpset file is the only help system file referenced explicitly by the application. The JavaHelp system derives all information about the help system from that file. If the helpset file is outside the JAR file, the installation program can update the helpset file so the JAR files can be installed anywhere in the user's file system. This is not possible if the helpset file is included in the JAR file.

Another advantage of locating the helpset file outside the JAR file is that it can be updated independently of the rest of the helpset. For example, additional help information can be added to the user's help system by adding more JAR files and updating the helpset file.

3.2 Map File

If the map file is located outside of the JAR file, all URLs in the map must use the jar: protocol.

For example:  

jar:file://c:/product/help/Ajar.jar!/File1.html


Excluding the map file from the JAR file is possible, but is usually not useful. 

 

4 Packaging a Helpset into a JAR File (CARMEN way to do it with HELEN)

To package the Help system in CARMEN using HELEN, you must simply select the option "PUBLISH" in the File menu.

You must only select the destination folder (the lib directory for CARMEN) and, be sure, you have set JavaHelp 2.0 compatibility.

By default, the name of the jar will be the name of the project which, as reminder, will be:

  • carmenHelp_en.jar - English Version
  • carmenHelp_es.jar - Spanish Version

 

5 Creating new CARMEN language dependant Help Projects

 

To create a new CARMEN Help Projects (really, when you want to add a new supported language to CARMEN) you must do the following steps:

  1. In the Carmen Help directories, select "carmenHelp_en" directory
  2. Make a copy with the name "carmenHelp_XX" where XX is the two letter for the locale you are adding to CARMEN
  3. Then, go to the new directory and rename the file "carmenHelp_en.jhp" with "carmenHelp_XX.jhp"
  4. Edit "carmenHelp_XX.jhp" file that contains the structure for the Helen Project with Wordpad or similar text editor (not with Helen)
    1. Find the line 
      <directory title="...(your directory).../Carmen/help/carmenHelp_en">
    2. Change the name of the file you will see from "carmenHelp_en" to "carmenHelp_XX"
    3. Save the file.
  5. Double click on the "carmenHelp_XX.jhp" file or, alternatively, Open Helen software and Select Open Project and select the directory you have created and open the Helen project file.
  6. You will now have opened the new project.
  7. Do translation of the HTML pages but do not change the name of the Html files.
  8. Do translation of the Index document (index.xml)
  9. Do translation of the TOC document (toc.xml)
  10. Do translation of the Glossary document (glossary.xml)
  11. Finally, select "Tools - Create/Update search files" to re-generate the search engine.

6. Setting Online Help with key "F1" from Carmen windows

JavaHelp offers several facilities to programmers to enhance the usability of the programs by adding support for F1 key in the several windows in the application.

In order to obtain an Online Help from the window, Carmen programmers must follow the next steps:

  1. Each dialog that F1 will be activated, you must insert the next method 
    /**
    * online help convenience method
    */
    private void setOnlineHelp(String onlineSection) {
        /**
         * auxiliar help Viewer
         */
         HelpViewer helpViewer = null;
         helpViewer = new HelpViewer();
         try {
             helpViewer.getHb().enableHelpKey(this.getContentPane(),
                                              onlineSection,
                                              helpViewer.getHs());
         } catch (BadIDException ex) {
             System.out.println("WARNING >> "+ ex.getMessage() );
             System.out.println(ex.getStackTrace());
         } catch (Exception ex) {
             System.out.println("WARNING >> "+ ex.getMessage() );
             System.out.println(ex.getStackTrace());
         }
    }
  2. Then, you must insert the call to this method in the constructor for your window dialog 
         /**
      * a example dialog constructor in one of any dialog class
      */
      public NetworkPropertiesDialog(Window owner, boolean newElement) {
	  super(owner);
	  newNetwork = newElement;
	  initialize();
	  setName("NetworkPropertiesDialog");
	  setLocationRelativeTo(owner);
          setOnlineHelp("Network Properties Dialog");
      }
  3. Please, note than in the first step (in the method), the component where you are related the Help is the ContentPane as JavaHelp has restrictions to work directly with JFrame, JDialog and JPanel.
  4. Please, note than, in the call to this method,  the string must be one valid HELP ID
